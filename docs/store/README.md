## App content answers

**Ads:** No ads.

**App access** (reviewers need to sign in): give Google a test student and a test parent account on your live server, with this note:
"Sign up needs a one-time code by email. Use these accounts instead. To see app lock, allow the Accessibility service when asked; to see the parent view, sign in with the parent account."
Create them on the live server after `scripts\configure-server.ps1` (real email) is set up, and keep them working during review.

**Target audience and content:** ages 9–12 (with parent), 13–15, 16–17, 18+ (students and parents). Because children are included, the **Families policy** applies:
- No ads and no third-party analytics SDKs (true for this app).
- AI content is generated by Google Gemini for study only, and users can report it (Report buttons in the AI helper and the exam review; reviewed in the Control Room → Reports).
- Under-15 students need a linked parent (enforced by the server).
- ⚠ Before launch, switch the Gemini key to a **paid** Google Cloud project: on the free tier Google may use prompts to improve its products, which is not appropriate for children's data.

**Content rating questionnaire:** Reference: "Education". No violence, sexual content, profanity, drugs, gambling or user-to-user chat. The AI helper is a study assistant with reporting. Expected rating: Everyone / PEGI 3.

**News app:** No. **COVID app:** No. **Government app:** No. **Financial features:** None.

## Permissions declarations

**Accessibility API** (Play Console → App content → Accessibility API). Use: *"Study Mate is a focus app. While a study session or a parent's lock is running, the Accessibility service detects when one of the apps the user chose to lock comes to the foreground (only its package name) and shows the study screen instead, until the user passes a quiz. It does not read text, input or screen content of other apps."*
In-app disclosure: App lock → Open settings shows "How app lock uses Accessibility" with **I agree / No thanks** before any settings open.
Video: `app-lock-disclosure.mp4` in this folder (1:12): App lock → Open settings → disclosure → I agree → enabling the service → a locked app. Uploaded unlisted: https://youtube.com/shorts/R0YiNJIH6CI (declared in Play Console on 4 Nov 2026).

**Usage access (PACKAGE_USAGE_STATS):** screen time for the linked parent. Requested from App lock step 2 with an explanation.

**Exact alarms (SCHEDULE_EXACT_ALARM):** calendar exam and class reminders at the right minute (a core calendar feature). The app works without it (reminders may then arrive a few minutes late).

**Camera:** photos of study pages, only when the user taps "Add a photo".

**Notifications:** reminders and study alerts.

## Before you press "Publish"
- [ ] Server: run `scripts\set-ai-key.ps1` (AI on) and `scripts\configure-server.ps1` (real email codes, production mode).
- [ ] Hosting: the server must be reachable 24/7 during review and after launch. A home PC with a quick tunnel is fine for testing but not for a public app: move the API to a cloud host with Postgres and a fixed HTTPS address, then rebuild with that `API_BASE_URL`.
- [ ] Create the reviewer test accounts (App access).
- [ ] Upload `app/build/app/outputs/bundle/release/app-release.aab` to an **internal testing** track first, install from Play on a real phone, run through sign-up, a study session, the lock and the quiz.
- [ ] Turn on **Play App Signing** (default). Keep `E:\dev\keys\study-assistant-upload.jks` and `E:\dev\keys\key.properties.backup` safe and backed up off this computer (e.g. a password manager or encrypted USB). If they are lost, Google can reset the upload key, but it takes days.
- [ ] Fill in the store listing, content rating, target audience, Data safety and Accessibility declaration from this page.

## Build the release
```bash
cd app
D=https://gist.githubusercontent.com/Ashfaq1306/73f5cd0421af834e9965f8680d2ea2b1/raw/study-assistant-endpoint.json
flutter build appbundle --release --dart-define=API_BASE_URL=https://study-assistant-api-jdgm.onrender.com --dart-define=API_DISCOVERY_URL=$D
```
Bump `version:` in `app/pubspec.yaml` (and `AppConfig.appVersion`) for every upload; the number after `+` must grow.
